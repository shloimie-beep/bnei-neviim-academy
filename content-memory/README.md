# BNA Content Memory

This folder is the repo-side content memory system.

Drive is useful for phone/browser access and human marketing review. The live
Drive mirror is `BNA V2 / 40 Content Library - Marketing`, generated by
`npm run content:sync-drive-library`. This repo folder is useful because the
Telegram bridge and coding agents can read it directly before generating drafts.
The long-term flow is:

1. Raw media lands in Telegram or Drive.
2. The system transcribes and parses it.
3. Draft generation reads:
   - `brand-kit/`
   - `content-memory/platform-prompts/`
   - `content-memory/prompt-patches/` when an output needs modular patches
     for video style, camera direction, ratios, audience, or review guardrails
   - `content-memory/*/examples.md`
   - recent approved outputs from the app database
4. Real content transcripts and website articles sync into Drive as readable
   Google Docs for article generation and marketing organization.
5. Approved drafts become examples for future drafts.
6. Brand-kit suggestions are reviewed before being promoted into stable voice.

The folders are not meant to be random storage. They are prompt context.

## Sourcing Lanes

- `source-sheets/`: student/class source sheets and worksheet mekoros. These
  prioritize direct Torah sources, Sefaria links, Hebrew excerpts, and
  classroom use.
- `public-bibliographies/`: second-stage sourcing for parent-facing videos,
  content rambles, website copy, newsletters, and social posts. These start
  from a claim audit and attach books, Torah sources where relevant, and
  scientific or educational literature with stable links when available.
- `prompt-patches/`: reusable prompt patch libraries. The first library is
  `rabbi-video-content/` for One Time/Rabbi video prompts, camera angles,
  aspect ratios, Jewish thematic visuals, and AI-video guardrails.
