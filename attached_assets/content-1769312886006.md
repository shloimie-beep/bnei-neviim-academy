# Working with Thumbnail Uploads

Want a quick, easy way to drive interest to a video? Upload a custom image file to use as the video's thumbnail. The _thumbnail_ is the static image that represents the video in search results and so on. It's the first impression of the video that the Vimeo community receives, so you want to pick an image that helps to tell the video's story.

If you're in the market to upload a thumbnail image to a video by way of the awesomeness of the Vimeo API, you're in exactly the right place. This guide covers everything that you need to know to do just that.

**NOTE:** This information is current for our latest API release, version 3.4. For complete details on 3.4, see our [Changelog](https://developer.vimeo.com/api/changelog).

## Before you begin

To use this guide, you need:

- **A video on Vimeo.** See [Working with Video Uploads](https://developer.vimeo.com/api/upload/videos) for more information.
- **An image file.** Use a common web format like JPEG or PNG. If you don't already have a thumbnail image, you can create one from a frame of the video. For more information, see [Creating a thumbnail](https://developer.vimeo.com/api/upload/thumbnails#creating-a-thumbnail) below.
- **An API application.** This is for making API requests. See [Getting Started: The Basics](https://developer.vimeo.com/api/guides/start) for details.
- **An access token with the `upload` and `edit` scopes.** This is the password to get past the bouncer. See [Getting Started: The Basics](https://developer.vimeo.com/api/guides/start) to learn more.

**NOTE:** You might also consider using our official libraries for PHP, Python, Node.js, and a dozen other programming languages. The libraries help to simplify complicated coding by handling all the HTTP requests on your behalf. For more information, see our [Libraries and SDKs](https://developer.vimeo.com/api/libraries) page.

## Uploading a thumbnail

Are you ready to upload a thumbnail? Great! We've got a couple of uploading options that you can choose from below, one for videos and one for events, and we'll walk you through each process.

### Uploading a thumbnail to a video

For uploading a thumbnail image to a video, the general API workflow is this:

- [**Step 1.** Get the URI of the thumbnail.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-1)
- [**Step 2.** Get the upload link for the thumbnail.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-2)
- [**Step 3.** Upload the thumbnail image file.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-3)
- [**Step 4.** Set the thumbnail as active.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-4)

We dig into the specifics in the following sections.

### [1](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-step-1)

#### Get the URI of the thumbnail

Whenever you upload a video to Vimeo, we set aside a URI to represent the video's thumbnails. Find this URI in the `metadata.connections.pictures.uri` field of the video representation, which you can retrieve from the API with an authenticated GET request:

```
GEThttps://api.vimeo.com/videos/{video_id}?fields=metadata.connections.pictures.uri
```

Refer to [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1) for the headers.

_Table 1. Headers for GET to `/videos/{video_id}`_

| Header | Set value to |
| --- | --- |
| `Authorization` | `bearer {access_token}` |
| `Accept` | `application/vnd.vimeo.*+json;version=3.4` |

**NOTE:** Don't omit the `Accept` header in this request (and all subsequent requests in this guide), and always be sure to set it to the given value. This ensures that the API handles your response according to version 3.4. For more information, see [Using Common Formats and Parameters](https://developer.vimeo.com/api/common-formats#using-the-accept-header).

Look for `metadata.connections.pictures.uri` in the response. You'll use this value in the next step.

### [2](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-step-2)

#### Get the upload link for the thumbnail

You obtain the location for uploading the thumbnail when you create the thumbnail's _resource_, or the placeholder for the image file on our servers.

To create this resource, refer back to the URI from the previous step, and send us the following authenticated POST request:

```
POSThttps://api.vimeo.com{pictures_uri}
```

For the headers, refer to [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1). You want `Authorization` as `bearer {access_token}` and `Accept` as `application/vnd.vimeo.*+json;version=3.4`.

The HTTP status of 201 Created indicates that your thumbnail resource is ready.

In the response from the API, look for the `link` field. The value of `link` gives the upload URL for [Step 3](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-3).

### [3](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-step-3)

#### Upload the thumbnail image file

All set with the `link` field from the previous step? It's time to upload the image file. For best results, we recommend that you send us a common web format like JPEG or PNG instead of something fancy.

The upload itself is just a PUT to the upload URL, where the body of the request contains the binary data of the image file:

```
PUT{link}
```

See [Table 2](https://developer.vimeo.com/api/upload/thumbnails#table-2) for the proper headers.

_Table 2. Headers for PUT to `{link}`_

| Header | Set value to |
| --- | --- |
| `Content-Type` | `image/jpeg` or `image/png`, depending on the image format |

If you see HTTP status 200 OK, the upload was successful.

### [4](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-step-4)

#### Set the thumbnail as active

A video can have multiple thumbnail images, but only one of them can be active at a time. So, in this final step, you mark the thumbnail that you just uploaded as the active one for the video. To do this, take the thumbnail URI from [Step 2](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-2), and PATCH to that location:

```
PATCHhttps://api.vimeo.com{pictures_uri}
```

See [Table 3](https://developer.vimeo.com/api/upload/thumbnails#table-3) for the headers.

_Table 3. Headers for PATCH to `{uri}`_

| Header | Set value to |
| --- | --- |
| `Authorization` | `bearer {access_token}` |
| `Content-Type` | `application/json` |
| `Accept` | `application/vnd.vimeo.*+json;version=3.4` |

In the body of the request, set the `active` parameter to `true`:

```
{ "active": true }
```

Look for HTTP status 200 OK. If you see it, all is well with the world, or at least with the active status of your thumbnail.

### Uploading a thumbnail to an event

If you're looking to upload a thumbnail image to an event, these are the steps to follow:

- [**Step 1.** Create the event and get the upload link.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-1)
- [**Step 2.** Upload an example thumbnail.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-2)
- [**Step 3.** Activate the thumbnail.](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-3)

We dive deeper into the process below.

### [1](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-to-a-live-event-step-1)

#### Create the event and get the upload link

Before you can upload a thumbnail to an event, you have to create the event. You create the event by sending a POST request to the following endpoint:

```
POSThttps://api.vimeo.com/me/live_events/{event_id}/pictures?fields=link,uri
```

The API response gives you the value of the `link` field, which is the upload link for [Step 2](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-2), and the `uri` field, which is the link for `pictures_uri` in [Step 3](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-3) below.

Header information is in [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1) above. You want to send `Authorization` as `bearer {access_token}`.

When you see the HTTP status of 201 Created, you're ready for [Step 2](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-2).

### [2](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-to-a-live-event-step-2)

#### Upload a thumbnail image

Remember the link that you generated in [Step 1](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-1)? Use that here to upload the thumbnail image that you want to use in either of these formats: `image/jpeg` or `image/png`.

To upload the thumbnail image, send a PUT to the upload URL:

```
PUThttps://api.vimeo.com{link}
```

See [Table 4](https://developer.vimeo.com/api/upload/thumbnails#table-4) for the headers.

_Table 4. Headers for PUT `{link}`_

| Header | Set value to |
| --- | --- |
| `Content-Type` | `image/jpeg` or `image/png`, depending on the image format |
| `Accept` | `application/vnd.vimeo.*+json;version=3.4` |

**NOTE:** The `Authorization` header isn't needed in this step.

In the body of the request, include the binary thumbnail data.

### [3](https://developer.vimeo.com/api/upload/thumbnails\#uploading-a-thumbnail-to-a-live-event-step-3)

#### Activate the thumbnail

Since you can have only one active thumbnail image at a time, activate the thumbnail image that you just uploaded for the event. You do this by taking the thumbnail URI from [Step 1](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-1) and PATCHing to that location:

```
PATCHhttps://api.vimeo.com{pictures_uri}
```

See [Table 3](https://developer.vimeo.com/api/upload/thumbnails#table-3) above for the headers.

In the body of the request, set the `active` parameter to `true`:

```
{ "active": true }
```

A returned HTTP status of 200 OK means that the active status of your thumbnail is good, as in awesome, just like you.

## Creating a thumbnail

You can upload your own image file to serve as the thumbnail if you want, but you can also create the thumbnail from a frame of the video.

To create the thumbnail, make sure that your app has an access token with the `upload` scope, and send the following authenticated POST request:

```
POSThttps://api.vimeo.com/videos/{video_id}/pictures
```

For the headers, use the ones from [Table 3](https://developer.vimeo.com/api/upload/thumbnails#table-3). Set `Authorization` to `bearer {access_token}`, `Content-Type` to `application/json`, and `Accept` to `application/vnd.vimeo.*+json;version=3.4`.

In the body of the request, set the `time` parameter to the time in seconds where we should grab the frame. While you're at it, set `active` to `true`, to turn on the thumbnail for active use:

```
{ "time": "{time}", "active": true }
```

The API returns HTTP status 201, meaning that the thumbnail is created.

## Changing the active status of a thumbnail

A video can have multiple thumbnails, but only one of them can be active, or visible, at a time. The thumbnail's `active` parameter controls this status, where `true` stands for active and `false` for inactive.

To change the active status of a thumbnail image through the API, use the following procedure:

- [**Step 1.** Get the URI of the thumbnail.](https://developer.vimeo.com/api/upload/thumbnails#change-active-status-of-a-thumbnail-step-1)
- [**Step 2.** Set the new active status.](https://developer.vimeo.com/api/upload/thumbnails#change-active-status-of-a-thumbnail-step-2)

Want some specifics? Keep reading.

### [1](https://developer.vimeo.com/api/upload/thumbnails\#change-active-status-of-a-thumbnail-step-1)

### Get the URI of the thumbnail

To start, send an authenticated GET request to `/videos/{video_id}/pictures`:

```
GEThttps://api.vimeo.com/videos/{video_id}/pictures
```

Include the same headers from [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1). You want `Authorization` as `bearer {access_token}` and `Accept` as `application/vnd.vimeo.*+json;version=3.4`.

The API returns a representation of all the thumbnails associated with the video. Find the `data.uri` field for the thumbnail that you want, and make a note of this value. Keep in mind that, when you have multiple thumbnails, each thumbnail image has its own `data.uri` field, so make sure that you get the right one.

### [2](https://developer.vimeo.com/api/upload/thumbnails\#change-active-status-of-a-thumbnail-step-2)

### Set the new active status

Using the URI from [Step 1](https://developer.vimeo.com/api/upload/thumbnails#change-active-status-of-a-thumbnail-step-1), and with an authorized request, PATCH us the new active status for the thumbnail:

```
PATCHhttps://api.vimeo.com{pictures_uri}
```

Take the headers from [Table 3](https://developer.vimeo.com/api/upload/thumbnails#table-3): `Authorization` as `bearer {access_token}`, `Content-Type` as `application/json`, and `Accept` as `application/vnd.vimeo.*+json;version=3.4`.

The `active` parameter goes in the body of the request:

```
{ "active": false }
```

Setting `active` to `false` deactivates the thumbnail.

The HTTP status 200 OK means that you've had spectacular success.

## Returning thumbnail links

You can return links to thumbnail images using a couple different approaches based on the dimensions of the thumbnails that you need. One approach is to return the links to all the various sizes of thumbnails that are associated with a video. The other is to return only those thumbnails that match the precise dimensions that you give.

Do we cover both approaches in the following sections? Of course we do.

### Returning links to all thumbnails

To return all thumbnail image links, send an authenticated GET request to `/videos/{video_id}/pictures`:

```
GEThttps://api.vimeo.com/videos/{video_id}/pictures
```

**NOTE:** If you're concerned about hitting request limits, try `GET https://api.vimeo.com/videos/{video_id}?fields=pictures` instead. This technique is called _field filtering._ To learn more, see our [Working with Rate Limits](https://developer.vimeo.com/guidelines/rate-limiting#avoid-rate-limiting) guide.

Be prepared to look through the results to find the link to the thumbnail that you need. If you happen to know the thumbnail's ID, you can save yourself the scavenger hunt by including the ID in the endpoint, like this:

```
GEThttps://api.vimeo.com/videos/{video_id}/pictures/{picture_id}
```

Use the same headers from [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1): `Authorization` as `bearer {access_token}` and `Accept` as `application/vnd.vimeo.*+json;version=3.4`.

The API returns multiple thumbnail links, and of different kinds. The base thumbnail link — that is, the no-frills link to the image file — appears in the `base_link` field. We also offer a set of standard-sized thumbnails at automatically generated preset dimensions. These appear in the response's `sizes.link` fields, along with separate versions of each size thumbnail with a built-in play button overlay in the `sizes.link_with_play_button` fields:

### Returning the thumbnails of a specific size only

To return the thumbnails of a specific size — one of our standard presets, your own custom dimensions — send an authenticated GET request to the `/videos/{video_id}/pictures` endpoint but with the `sizes` parameter appended, like this:

```
GEThttps://api.vimeo.com/videos/{video_id}/pictures?sizes={width}x{height}
```

Supply the desired width and height in the `{width}` and `{height}` placeholders; the units are pixels. As for the headers, see [Table 1](https://developer.vimeo.com/api/upload/thumbnails#table-1). That's `Authorization` as `bearer {access_token}` and `Accept` as `application/vnd.vimeo.*+json;version=3.4`.

**NOTE:** For more information on the `sizes` parameter, see [Using Common Formats and Parameters](https://developer.vimeo.com/api/common-formats#using-the-sizes-parameter).

Example time. You want only the 150 ✕ 100 thumbnail for the video with the ID of 286898202. You send your authenticated GET request to `https://api.vimeo.com/videos/286898202/pictures?sizes=150x100.` The API gives you back this response:

## Caching thumbnails

The links to the thumbnails are valid for one hour from the API response. If you need to access these images past that time, say because they're embedded on your website, try either of these alternatives:

- [**Option 1.** Download the image file.](https://developer.vimeo.com/api/upload/thumbnails#download-image-file)
- [**Option 2.** Refresh cached thumbnail links every hour.](https://developer.vimeo.com/api/upload/thumbnails#refresh-cached-thumbnail-links-every-hour)

For more details, see the following sections.

**NOTE:** You might not need to worry about caching thumbnails if you only use the Vimeo Player. Our player automatically displays the most up-to-date thumbnail image.

### Option 1. Download the image file

You can download the thumbnail for storage on your own CMS or hosting provider. Use a cURL command to retrieve the image, like this:

```
curl https://i.vimeocdn.com/video/123456789-ba7816bf8f01cfea414140de5dae2223b00361a396177a_100x75.jpg --output 123456789.jpg
```

Note the **`output`** argument, which indicates the file name of the image.

### Option 2. Refresh the cached thumbnail links every hour

If you'd prefer Vimeo's hosted images, you can refresh the cached thumbnail links every hour, before they expire. These URLs are subject to change, so you should refresh them regularly wherever you use them to avoid the risk of your links breaking.

To refresh the cache, follow the same procedure from [Returning thumbnail links](https://developer.vimeo.com/api/upload/thumbnails#returning-thumbnail-links) above. And for best practices on caching, refer to our [Guidelines for Developers](https://developer.vimeo.com/guidelines#best-practices).

## Handling errors

Since nothing ever goes wrong and nothing unexpected ever happens, we're not sure why we're discussing these common upload error cases, but whatever.

Even more useless information about less frequent errors appears in our [API Reference](https://developer.vimeo.com/api/reference/videos#upload_video).

### HTTP status code 4XX

An HTTP status code in the 400s, such as 410 Gone, probably means that you're trying to upload to a bad or expired link. To generate a new link, go back to [Step 1](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-step-1) of the thumbnail upload process for a video or [Step 1](https://developer.vimeo.com/api/upload/thumbnails#uploading-a-thumbnail-to-a-live-event-step-1) of the thumbnail upload process for an event, whichever brought you here, and run the upload again.

If you get the 400 Bad Request status code after the POST or PATCH request in either process, you likely have a bad parameter in either the header or the body. Make sure that the parameter name is accurate and that you're sending the right data type.

### HTTP status code 5XX

If the API gives you an HTTP status code in the 500s, such as 500 Internal Server Error, we're experiencing some sort of problem with our server. Please wait a couple minutes and try again. If the same status code keeps coming back, [tell us about it](http://www.vimeo.com/help/contact).

### Error code 8003: unrecognized access token

If you receive error code 8003 and HTTP status 401 Authorization Required, check the access token string that you're supplying, because the API doesn't recognize it:

```
{
  "error": "Something strange occurred. Please get in touch with the app's creator.",
  "link": null,
  "developer_message": "The app didn't receive the user's credentials.",
  "error_code": 8003
}
```

If the string is fine but you get this error anyway, see our [authentication documentation](https://developer.vimeo.com/api/authentication) for additional help.
