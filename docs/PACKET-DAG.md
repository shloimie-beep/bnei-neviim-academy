# Packet DAG

A Packet DAG is required for super-rambles. It prevents a broad ramble from
becoming one giant Codex implementation prompt.

## Required Packet Fields

Each packet must include:

- `packet_id`;
- `parent_raw_id`;
- `parent_packet_id`;
- `child_packet_ids`;
- `depends_on_packet_ids`;
- `blocks_packet_ids`;
- `stage`;
- `packet_role`;
- `status`;
- `owner`;
- `scope`;
- `out_of_scope`;
- `consumes`;
- `produces`;
- `affected_routes`;
- `affected_files`;
- `view_classes`;
- `required_evidence`;
- `validation_command`;
- `terminal_condition`;
- `handoff_target`;
- `next_packet`.

## Default Rabbi / One Time DAG

`00-control-tower`

- depends on raw capture;
- produces packet manifest, source statement map, child packet list.

`01-current-state-visual-audit`

- depends on `00-control-tower`;
- produces screenshots, VQ findings, route/screen inventory, action-state
  inventory, role/scope leakage findings, and implementation packet proposals.

`02-ia-nav-filter-spec`

- depends on `01-current-state-visual-audit`;
- produces IA/nav/filter implementation packet.

`03-crm-pipeline-spec`

- depends on `01-current-state-visual-audit`;
- produces CRM/pipeline implementation packet.

`04-community-classes-questions-spec`

- depends on `01-current-state-visual-audit`;
- produces community/classes/questions implementation packet.

`05-communications-readiness-spec`

- depends on `01-current-state-visual-audit`;
- produces communications UI packet and separates provider setup if needed.

`06-payments-access-status-spec`

- depends on `01-current-state-visual-audit`;
- produces payments/access UI status packet and separates Stripe setup if
  needed.

`07-mobile-polish-spec`

- depends on relevant implementation packets;
- produces mobile cleanup implementation packet.

`08-accessibility-and-security-audit`

- depends on relevant implementation packets;
- produces accessibility/security fixes or blockers.

`09-verifier-deploy-closeout`

- depends on all implementation packets;
- produces final verification, deploy/live smoke, changelog, and next-session
  evidence.

## Child Packet Rule

A child packet may be generated by a separate ChatGPT window. It must state:

> You are Stage X of parent raw input RAW-YYYYMMDD-###. Do not solve the whole
> parent ramble. Produce only this packet's output contract.

If a child packet exceeds context budget or touches too many surfaces, split it
again and update the parent manifest.
