Title:
Product Quality Compiler Validator + Protocol Drift Watchdog

Primary objective:
Turn the Product Quality Compiler / Super-Ramble Packet Splitter protocol from
documentation into an enforced operating system.

Operator intent to preserve:
- Shloimie wants to ramble vaguely.
- The assistant/agent must compile vague rambles into exact implementation specs.
- "Make it look nice" must become a professional, enforceable product-quality packet.
- "Million-dollar app" means visual polish, workflow completeness, speed, credibility, responsiveness, accessibility, data clarity, and actual working states.
- The protocol must not remain optional documentation.
- Missing scope, screenshots, roles, blockers, done criteria, or out-of-scope must fail validation.
- UI cleanup requires screenshots and mobile proof.
- App-visible work requires deploy/live-smoke proof.
- No GHL. "GHL-like" means first-party CRM patterns only.
- Broad rambles should split into multiple ChatGPT prompt-generation packets when needed.
- Each packet must know which stage of the parent ramble process it belongs to.
- Final implementation packets should be independently runnable where possible, with one control-tower verifier at the end.

Required additions:
1. machine-readable schema validation;
2. Definition of Ready gate before Codex implementation;
3. Definition of Done gate after implementation;
4. state matrix requirement for every UI screen;
5. executable visual/accessibility harness contracts;
6. agent eval fixtures for vague ramble compilation;
7. browser-agent security rules;
8. trace/observability requirements;
9. UI pattern reference map;
10. protocol drift watchdog;
11. package scripts/tests that fail when protocol packets are vague or incomplete.

Hard boundaries:
- Do not implement Rabbi CRM UI in this task.
- Do not send email.
- Do not run Stripe.
- Do not mutate external providers.
- Do not add GHL runtime.
- This is a protocol/tooling enforcement task.
