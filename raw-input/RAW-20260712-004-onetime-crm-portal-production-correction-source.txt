CURRENT-STATE TRUTH

The audit established the following facts:

- An Operations URL with workspace=rabbi_sheller_provider but no view_as_rabbi token is normally the existing authenticated user—often the platform super-admin—viewing the One Time workspace.
- A URL containing view_as_rabbi=<signed token> is a super-admin-created, read-only impersonation preview.
- The read-only token currently blocks non-GET requests but does not fully replace the underlying super-admin identity or force every GET request to remain in the One Time workspace.
- The One Time CRM currently renders approximately 503 contacts simultaneously.
- CRM contact selection calls the application-wide render function before and after loading the timeline.
- The contact route also loads many unrelated datasets.
- “Bna Contacts” and “Bna Parent Leads” are internal source-table names leaking into customer-facing UI.
- Some contact-card enrichment queries match communication, support, task, or membership records by email without consistently applying workspace/project restrictions.
- The faded contact text is caused by a CSS cascade: a later stylesheet turns cards white while child text remains nearly white.
- The apparent mobile hamburger on several preview pages is a CSS pseudo-element, not a real clickable button.
- Parent, student, member, classroom, and library pages use several unrelated headers and footers.
- `/one-time-parent` is currently password setup/reset, not a complete parent portal.
- `/rabbi-member` is functioning as the family/member home but is ambiguously named.
- Preview navigation sometimes drops review mode and lands on production/login routes.
- Fake One Time identities already exist, but only one student is wired into the visible review flow.
