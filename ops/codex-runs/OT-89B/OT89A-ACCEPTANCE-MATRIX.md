# OT89 Acceptance Matrix

Every row is mandatory. Evidence must be recorded in the appropriate `ops/codex-runs/OT-89A/` or `ops/codex-runs/OT-89B/` task files and linked from the draft pull request. A row passes only with an automated test or a reproducible command plus captured result; prose assertions alone do not pass.

| ID | Area | Packet | Required evidence and pass condition |
|---|---|---|---|
| `CONTRACT-01` | Frozen contract | Both | The committed contract is byte-for-byte identical to `SUPPORT-EVENT-CONTRACT.json` in this packet and its SHA-256 matches `SHA256SUMS.txt`. JSON Schema validation accepts the included example and rejects an unknown field, category, event type, and contract version. Both implementations reproduce the frozen HMAC interoperability vector exactly. |
| `BASE-01` | OT89A base | OT89A | `git ls-remote` proves `codex/ot84-telegram-action-gateway` exists remotely. The run record contains its resolved commit and the new branch is based on that exact commit. |
| `BASE-02` | OT89B isolation and base | OT89B | The existing `C:\Users\User\BNA v2.0` worktree has identical status, HEAD, index, and tracked-file hashes before and after the run. The run record contains the read-only origin URL, resolved remote default/stable control-plane branch, and base commit used by the clean isolated clone/worktree. |
| `AUTH-01` | Anonymous route | OT89A | `ot89a_auth_anonymous_route_hidden` proves an anonymous request cannot render or submit a ticket and no public ticket endpoint appears in navigation, sitemap, static export, or robots-visible content. The public page exposes only the existing WhatsApp lead path. |

| `ATT-02` | Malicious attachment | OT89A | `ot89a_attachment_malicious_rejected` covers MIME spoofing, SVG/HTML/PDF/archive/executable/polyglot content, path traversal filename, NUL/control characters, decompression bomb, and invalid UTF-8. |
