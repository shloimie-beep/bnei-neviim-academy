Captured as planning only. I would split this into 3 layers.

Student page design:
Option A: Goal Board
Clean mobile task-manager layout. Top section is school-tracked Torah progress with circles, percentage, morning goal, and today status. Below that is the student's own goals, grouped by Today, Upcoming, Waiting, Done. Best fit.

Option B: Schedule Lite
Still clean, but items can show optional times. Not a full calendar. Good if assignments need "watch this at 7:30" without making the whole page feel like a timetable.

Option C: Accountability Journal
More private-meeting focused. Goals, reflections, consequences, and progress notes are central. Better for mentoring, less good as a daily task app.

My recommendation: Option A, with optional time display from Option B.

Google Classroom layer:
- Admin creates/syncs students and classrooms.
- You paste a YouTube link.
- Pick student or class.
- Set due date/time.
- Codex generates assignment title, instructions, and optional multiple-choice questions.
- Assignment posts to Google Classroom.
- Submission/completion status feeds back into the student's Accountability page.

Natural consequences/filter layer:
- During private meetings, student chooses consequences for missed goals.
- Each assignment can have a linked consequence.
- If missed, the system marks it as "consequence pending" first.
- Filtering should only activate through a parent/admin-approved device-control tool, not silently.
- Student should have a recovery path: finish assignment, submit reflection, or reschedule with approval.

Design decision to make first:
Option A: Build student Goal Board first
Option B: Build Google Classroom assignment builder first
Option C: Map device filtering rules first

I recommend Option A first, then Classroom, then filtering. The student page is the base that everything else connects into.

Tasks, Students, Content, Contacts, or Accounting.

6. After Codex finishes repo work, Telegram gets the result

Telegram is the input.
Codex is the worker.
Operations is the organized dashboard.
Changelog is the record of completed machine work.
